# Prompt: Build the Galaxy Forge Weapon Engine

You are extending this repo, a Minecraft **Bedrock** addon (packs `GalaxyForge_BP` / `GalaxyForge_RP`, generated by Python under `tools/creatures/`). Target platform is **PlayStation 5 via a Realm or a hosted world**, so everything must be console-safe. The player is a kid (Parker) who wants breathtaking, visually complex sci-fi weapons: scopes, laser dots, fireballs, beams, plasma. 50 weapons are specced in `docs/weapons/WEAPONS.md`.

Do not build 50 bespoke implementations. Build **one engine and ~10 archetypes**, then express each weapon as data plus unique VFX. Read this whole file, then `tools/creatures/lib.py`, `tools/creatures/extras/military_pack.py` (sabers, grenades, projectile entities, `Icon`, `write_item`), `tools/build.py`, and `README.md` before writing code.

Do not use the name or likeness of any real streamer in item names, lang strings, or textures.

## Hard platform constraints (these drive the design)

1. **Stable Script API only.** Add a `script` module (JavaScript, no bundler, no npm, no TypeScript toolchain) to `GalaxyForge_BP/manifest.json` using `@minecraft/server` (and `@minecraft/server-ui` only if needed). Pin the newest **stable** (non-`-beta`) version supported by the `min_engine_version`; verify against current Microsoft docs, don't guess. **Never use beta APIs**: they require the "Beta APIs" experiment toggle, which breaks Realms and console joins. Bump `version` in both manifests (see README).
2. **No custom JSON UI.** It doesn't work reliably on console. Scopes, crosshairs, heat gauges, and lock-on reticles are drawn with `player.onScreenDisplay.setTitle/updateSubtitle/setActionBar` using **custom font glyphs** (`RP/font/glyph_E1.png` etc., private-use codepoints). The glyph sheet is a texture you generate with Python (PIL is fine). Title overlays are a known technique on console. Spike it first (see Phase 0).
3. **No custom `.ogg` unless you can generate one deterministically.** Layer vanilla sounds (`dimension.playSound`/`player.playSound` with pitch and volume) per weapon: e.g. `random.explode` at pitch 2.0 plus `beacon.activate` for a laser thump. Define each weapon's sound recipe as a list of `(sound, volume, pitch, delay_ticks)`.
4. **Custom particles are fine** (`RP/particles/*.json`, Molang variables via `MolangVariableMap`). This is your main VFX tool. Emissive entity/attachable textures use the existing `lib.glow()` / `entity_emissive_alpha` convention.
5. **Script budget.** Bedrock's watchdog kills scripts that stall a tick. One global `system.runInterval` (every tick) drives all weapons. Per-tick caps: raycasts, particle spawns, entity queries. No `runCommand` in hot paths; no per-weapon intervals; no unbounded loops.
6. **Held-item look.** Use **attachables with custom geometry** (see `RP/attachables/`) so each weapon has a real 3D model in first and third person, with emissive parts. Generate geometry from Python specs the way `tools/creatures` does (integer cubes, unique UVs, no `mirror`). Every weapon needs a distinct silhouette.
7. **Griefing and safety defaults.** Weapons never damage: `galaxy:pup`, any tamed entity, or players (unless `pvp` is on). Block-affecting effects (melting, cutting, craters) run only when `mobGriefing` is true, and cap blocks changed per shot.

## Architecture

```
tools/weapons/
  archetypes.md          # your design notes, keep short
  defs/*.py              # one module per family, each exports WEAPONS = [dict, ...]  (data only)
  model.py               # geometry + texture generation for the held models (reuse lib helpers)
  particles.py           # generates RP/particles/*.json from parametric templates
  glyphs.py              # generates font glyph sheet: crosshairs, scopes, gauges
  build_weapons.py       # emits items, attachables, recipes, particles, lang, and scripts/generated/weapons.js
packs/GalaxyForge_BP/scripts/
  main.js                # registers item components, global tick loop
  engine/{state,input,ray,scope,hud,heat,damage,vfx,sound,safety}.js
  archetypes/{hitscan,bolt,beam,charge,cone,lob,chain,deploy,field,tether}.js
  generated/weapons.js   # written by build_weapons.py, never hand-edited
```

Hook `build_weapons.py` into `tools/creatures/build_all.py` the same way `extras/multitool.py` is hooked, so `python3 tools/creatures/build_all.py` regenerates everything. `tools/build.py` must validate the new manifest module and that every weapon has its item JSON, attachable, icon texture, lang entry, and recipe.

### Input model (decide once, use everywhere)
- **Fire**: use-and-hold via `itemStartUse` / `itemReleaseUse` / per-tick "is using item" tracking. Weapons declare `use_duration` in the item JSON so the use animation loops. Semi-auto = one shot per press; auto = while held; charge = fire on release.
- **Aim (ADS)**: sneak toggles scope. While aimed: laser dot on, scope glyph overlay, optional zoom. Player must be visibly "aiming" in third person too (attachable animation keyed on `q.is_sneaking`).
- **Alt-fire**: sneak + use.
- **Reload/vent**: use on empty, or drop-swap. Reload is a short timed action with a glyph progress bar, not an inventory chore.

### Zoom
Bedrock has no stable FOV setter. Phase 0 must spike, in this order, and record which works on **console**: (a) `player.camera` stable APIs, (b) Slowness effect with hidden particles to narrow FOV, (c) the overlay glyph alone (no real zoom; magnify by drawing a vignette and drawing the reticle at range). Pick one, implement `scope.js` behind an interface so weapons only say `zoom: 4`.

### Laser dot
While aimed (or always, if `dot: "always"`), each tick raycast from the eye along the view vector (`dimension.getBlockFromRay` + `getEntitiesFromRay`, max range from the def). Spawn one particle at the hit point (`gx:laser_dot`, color/size molang vars). Visible to all players, so it's also a gameplay "I'm aiming at you" tell. Dot has 3 styles: `point`, `ring`, `cross`. Cap: 1 dot particle per weapon per tick, every 2nd tick is fine.

### Weapon state
Per-player, in-memory `Map` cleaned on `playerLeave`. Persistent per-item data (ammo, heat, mode) via `ItemStack.setDynamicProperty`, written on unequip/fire-end, not every tick. Ammo is energy: a craftable `gx:energy_cell` item consumed on reload, plus the weapon's internal magazine. Weapons with `ammo: "infinite"` use heat instead.

### Archetypes (implement each once, parameterize heavily)
| id | behavior | key params |
|---|---|---|
| `hitscan` | instant ray, tracer particle | range, pierce, ricochet, tracer style, falloff |
| `bolt` | script-simulated projectile (ray-march per tick, **no entity**), cheap | speed, gravity, homing, lifetime, split, bounce, on_hit chain |
| `beam` | channeled continuous ray, tick damage, heat | dps, width, refract, spin_up, heat_rate |
| `charge` | hold to charge, tiers on release | tiers[{ticks, effect}], overcharge_penalty |
| `cone` | short-range spray | angle, range, dps, status |
| `lob` | arcing entity/bolt with fuse | gravity, fuse, aoe, on_land (field) |
| `chain` | arc between N nearest targets | jumps, radius, falloff |
| `deploy` | spawns a gx entity (turret, drone, portal) | entity id, duration, cap per player |
| `field` | persistent zone with tick effects | radius, duration, pull/push, dps |
| `tether` | ray attaches, then pull/reel | pull target/self, max length |

`on_hit` and `on_tick` hooks are small declarative effect lists, e.g. `[{"dmg": 6, "type": "fire"}, {"status": "slowness", "ticks": 40, "amp": 2}, {"vfx": "gx:plasma_burst"}, {"spawn_field": "singularity"}]`. Effects are a fixed vocabulary in `damage.js`. A weapon's **signature twist** (each spec has one) is a hook plus, at most, ~60 lines of weapon-specific code in `archetypes/custom/<id>.js`. If a twist needs more than that, cut it down.

### VFX standard (this is the point of the project; do not phone it in)
Every weapon must have all six, written down in its def and distinct from the others:
1. **Idle**: emissive parts on the held model, a subtle ambient particle (embers, static, frost, motes) at low rate.
2. **Charge/spin-up**: particles converge on the muzzle, model animates (coils rotate, vents open).
3. **Muzzle flash**: unique shape and color, 2-4 particles, lasting ≤6 ticks.
4. **Projectile/beam body**: core + glow halo + trail; beams are chains of billboard particles spaced ~0.5 blocks with a `sin`-based shimmer; use a max of ~40 per shot.
5. **Impact**: flash + shockwave ring + debris/sparks + lingering scorch or glow for 20-40 ticks.
6. **Screen feedback**: title-glyph flashes (hit marker, kill-confirm tick, vignette on overheat/charge). No fake camera shake via knockback.

Particle templates in `particles.py` (`beam_segment`, `orb`, `ring_wave`, `spark_burst`, `smoke_trail`, `star_flash`, `lightning_fork`, `swirl`, `dot`) take color ramps and lifetimes; weapons instantiate them, so the whole VFX vocabulary is ~10 templates × many palettes, not 200 hand-written files.

## Definition of done (per weapon)
- Item, attachable, model, emissive texture, 16×16 icon, lang name+description, recipe, energy-cell cost.
- All six VFX layers exist and are visibly distinct from every other weapon (compare particle palette + shape + model silhouette against the whole table).
- Scope + dot behave as specced; HUD glyphs show ammo/heat/charge.
- Safety filter verified (pup, tamed, players, griefing gate).
- Numbers from the spec are in the def; balance is by the **DPS budget**: common ≈ 8 dps sustained, rare ≈ 14, epic ≈ 22, mythic ≈ 30 at a comparable range; ultimates trade DPS for burst with a ≥ 45 s cooldown.
- `python3 tools/build.py` passes; `.mcaddon` builds; a `docs/weapons/TESTING.md` checklist tells Lee exactly what to try in-game for each weapon in under 30 seconds.
